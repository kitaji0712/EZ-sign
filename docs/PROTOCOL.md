# EZ Sign の通信手順

Santek EZ Sign（NFC モデル）は ISO 14443-4（ISO-DEP）のタグとして動きます。画像の書き込みは ISO 7816-4 形式の APDU だけで完結します。

この手順は公式資料ではありません。次の 2 つの有志の実装をもとにしています。

- [fossasia/magic-epaper-app PR #688](https://github.com/fossasia/magic-epaper-app/pull/688): 2.13 インチ用の Android 実装。手順の出どころ
- [nThanksForAllTheFish/ezsign-nfc](https://github.com/nThanksForAllTheFish/ezsign-nfc)（MIT）: PC/SC リーダーで 4.2 インチ・2.9 インチの動作を実機で確認（2026-10-24）

## 手順

| 順番 | コマンド | APDU | 備考 |
|---|---|---|---|
| 1 | SELECT | `00 A4 04 00 07 D2 76 00 00 85 01 01` | NFC Forum Type 4 の NDEF アプリ |
| 2 | VERIFY | `00 20 00 01 04 20 09 12 10` | 固定の 4 バイト鍵。失敗したら 300 ms 待って 1 回だけ再試行 |
| 3 | SELECT | 1 と同じ | |
| 4 | INIT | `00 D1 00 00 00` | 書き込み開始。応答に機種情報（TLV） |
| 5 | DATA × N | `F0 D2 <番号 2 バイト> <長さ> <最大 250 バイト>` | 番号は 0 から順に |
| 6 | REFRESH | `F0 D4 85 80 00` | 描画開始 |
| 7 | POLL（繰り返し） | `F0 DE 00 00 01` | 応答の 1 バイト目が `00` なら完了。REFRESH の 1.5 秒後から 0.2 秒おき |

成功時の状態語は `90 00` です。

このアプリでは手順 1 の前に、独自の「位置確認」として SELECT を 8 回（0.1 秒おき）送り、すべて `90 00` が返ったときだけ書き込みを始めます。当てる位置がずれていて電力や通信が不安定なまま、約 25 秒の描画に入らないようにするためです。公式アプリの確認方法は分かっていません。

## 画像の形式

- 1 画素 2 ビット。バイトの上位ビットから詰めます
- 色の番号: `0` 黒、`1` 白、`2` 黄、`3` 赤
- 画素の並び順は機種で違います（`Sources/EZSignCore/PanelModel.swift`）

| 機種 | 解像度 | フレームバッファ | DATA の数 | 並び順 | 描画時間（PC で計測） |
|---|---|---|---|---|---|
| 4.2 インチ | 400×300 | 30,000 バイト | 120 | 行優先・左右反転（`row-mirror`） | 約 24 秒 |
| 2.9 インチ | 296×128 | 9,472 バイト | 38（最後は 222 バイト） | 列優先（`col`） | 約 20 秒 |
| 2.13 インチ | 250×128 | 8,000 バイト | 32 | 列優先・左右反転（`col-mirror`） | — |

## INIT の応答

タグ・長さ・値の並びです。4.2 インチの実機の例（ezsign-nfc）:

- `A0`: `F0 07 20 02 58 01 90`。`01 90`（= 400）が幅で、機種の判別に使います
- `C0`: シリアル番号（ASCII）
- `C1`: UID

## iPhone（Core NFC）での注意

- `NFCTagReaderSession` を `.iso14443` で使います。entitlements の `com.apple.developer.nfc.readersession.formats` は `TAG` だけにします。
- Info.plist の `com.apple.developer.nfc.readersession.iso7816.select-identifiers` に `D2760000850101` を入れると、iOS が検出時にその AID を SELECT し、`NFCISO7816Tag` として渡してくれます。（今は 4 回目の実験のため外しています。下を参照）
- NFC の機能は有料の Apple Developer Program でしか使えません（無料の Personal Team では不可）。
- 1 つのセッションは約 60 秒まで、タグとの接続は約 20 秒までという報告があります（[Apple Developer Forums](https://developer.apple.com/forums/thread/802895)）。公式アプリは iPhone で 30 秒以上かけて書き込めているので、何らかの方法で続けられるはずです。

### 実機の結果（2026-10-29、iPhone18,3 / iOS 27.0、4.2 インチ）

1 回目の書き込みでは次のようになりました。

| 項目 | 結果 |
|---|---|
| タグの見え方 | ISO 7816（AID `D2760000850101`）。検出まで 0.5 秒 |
| 位置確認（SELECT × 8） | 応答 平均 6 ms / 最大 7 ms |
| SELECT / VERIFY / INIT | すべて `90 00`。INIT の `A0` から 4.2 インチと判別できた |
| DATA × 120 | 1 回 35 ms、合計 4.4 秒 |
| REFRESH | 応答まで 1.2 秒 |
| POLL | REFRESH から 13.4 秒まで `01`（描画中） |
| 切断 | **接続から 20.5 秒で POLL が NFCError 103（Session invalidated）** |
| パネル | 描画の途中で止まった。配置は正しく、左右反転もなし（`row-mirror` で正しい） |

2 回目は、接続から 17 秒で `restartPolling()` してつなぎ直そうとしました。

| 項目 | 結果 |
|---|---|
| つなぎ直し | `restartPolling()` の後、描画中のパネルは **再検出されなかった** |
| 切断 | セッション開始から 21.1 秒（検出から 19.9 秒）で **NFCError 202（Session invalidated unexpectedly）** |
| パネル | また描画の途中で止まった |

この時点では、2 回ともセッション開始から約 21 秒で終わったので「セッションごとの上限」と考えましたが、3 回目の結果で違うと分かりました（下）。なお、`restartPolling()` で延ばせる iPhone もあるが iPhone 15 / 16 では失敗した、という ST のフォーラムの書き込みがあります。

公式アプリは、読み取り画面を**一度も閉じずに**約 30 秒で書き込めます（利用者が確認）。% が進む転送はすぐ終わり、長いのはそのあとの描画です。また、EZ Sign を認識してから % が出るまでは、公式アプリの方がこのアプリより遅いそうです。

3 回目は、接続から 15.3 秒で POLL をやめ、セッションは開いたまま待ちました（「静かに待つ」）。

| 項目 | 結果 |
|---|---|
| 接続 | セッション開始から 3.8 秒 |
| REFRESH | セッション開始から 10.4 秒 |
| セッション終了 | セッション開始から **26.9 秒**（接続から 23.1 秒）で NFCError 202 |
| パネル | 1 回目とほぼ同じ所で描画が止まった |

同じ方式でもう一度試したときも、接続から 23.0 秒（セッション開始から 25.7 秒）で 202 になり、同じ所で描画が止まりました（再現した）。

セッションは 21 秒を越えて生きていたので、上限はセッションごとではありません。3 回の結果をまとめると、次のように考えられます。

- ISO 7816 タグとして渡された接続は、**接続から約 20 秒で打ち切られる**（1 回目は 20.5 秒で 103）
- 打ち切られると iOS はタグを探し直し、そのときに電波が途切れて、パネルの描画が止まる（1 回目と 3 回目は REFRESH から約 14 秒で止まり、写真もほぼ同じ）
- 描画中のパネルは応答できないので、探し直しに失敗し、約 3 秒後にセッションが終わる（2 回目と 3 回目の 202）

REFRESH のあと約 24 秒、電波を途切れさせずに出し続ける必要がありますが、1 つの接続では約 13〜14 秒しか確保できません。

### 4 回目の実験: MIFARE タグとして受け取る

公式アプリは認識から % が出るまで遅いので、このアプリとは違う方式でタグとつないでいる可能性があります。そこで Info.plist から AID（`D2760000850101`）を外しました。こうすると iOS は EZ Sign を `NFCMiFareTag` として渡します。この方式でも接続から約 20 秒の上限がかかるかを確かめます。

- 送り方: family が Plus / DESFire なら `sendMiFareISO7816Command`、それ以外（unknown）は APDU のバイト列をそのまま `sendMiFareCommand` で送り、応答の末尾 2 バイトを SW1 SW2 とする。最初の 1 回が通信以外の理由で失敗したら、もう一方の送り方を試す
- 描画中の待ち方は「POLL し続ける」（既定）。上限がかかればそのときの時刻とエラーがログに出る
- ISO 7816 に戻すには、Info.plist に `com.apple.developer.nfc.readersession.iso7816.select-identifiers` = [`D2760000850101`] を戻す

描画中の待ち方は、ほかに「静かに待つ」（接続の上限の 1.5 秒前に POLL をやめ、REFRESH から 26 秒まで待ってから確かめる）と「セッション切り替え」（上限の前に新しいセッションへ切り替える）も選べます。どの方式でも、通信が一時的に切れた場合（100 / 101 / 102 / 104）は、同じセッションで `restartPolling()` してつなぎ直します。
